# รายการตรวจก่อนเปิดจริง

สถานะ ณ 28 พ.ย. 2026 · รายละเอียดของโควตาและการสมัครอยู่ใน [rate-limit.md](rate-limit.md)

## 1. โค้ดที่ยังขาด

- [ ] **เพิกถอน token ของ Sign in with Apple ตอนลบบัญชี** — Apple ระบุว่าแอปที่ใช้ Sign in with Apple ควรทำ ต้องขอ authorization code ใหม่ในแอปและเรียก API ของ Apple จาก server ด้วย key `.p8` จำเป็นก่อนส่งรีวิวถ้าเปิดปุ่ม Apple
- [ ] ตัดสินใจว่าข้อความของรายการที่ลบแล้วจะเก็บถึงเมื่อไร (ตอนนี้เก็บจนลบบัญชี)

## 2. Supabase

- [ ] อัปเกรดองค์กรเป็น Pro (ตอนนี้ Free: Storage รวม 1 GB และโปรเจกต์ถูกพักเมื่อไม่มีการใช้งาน)
- [ ] ตรวจว่า spend cap เปิดอยู่ และตั้งการแจ้งเตือนค่าใช้จ่าย
- [ ] เปิด Leaked password protection (Authentication)
- [ ] ถอนสถานะทดสอบ: `update public.subscriptions set manual_until = null;`

## 3. ผู้ให้บริการ AI (ตอนนี้ใช้ Gemini)

- [ ] ใช้ key จากโปรเจกต์ที่เปิด billing (แบบฟรีนำข้อมูลไปปรับปรุงผลิตภัณฑ์)
- [ ] ตั้ง budget alert ใน Google Cloud Billing (เป็นการแจ้งเตือน ไม่ตัดการใช้งาน) และจำกัดโควตา request ของ API
- [ ] ตั้ง secret `AI_GLOBAL_DAILY_CAP` ให้ตรงกับงบ — ค่าเริ่มต้น 2000 คำขอ/วัน คิดเป็นราว $1.7 ที่ขนาดคำขอที่เคยวัด ($0.0008, ตัวอย่างเดียว) และราว $27 ถ้าทุกคำขอใหญ่สุดตามเพดาน
- [ ] ทดสอบคุณภาพภาษาไทยกับข้อความหลายแบบ

## 4. การสมัครสมาชิก

- [ ] ทำตาม "ตั้งค่าที่ต้องทำเอง" ใน [rate-limit.md](rate-limit.md) ข้อ 6
- [ ] กด test event ใน RevenueCat แล้วได้ 200
- [ ] ซื้อ sandbox บนเครื่องจริงทั้งสองแพลตฟอร์ม: ซื้อ ต่ออายุ ยกเลิก หมดอายุ คืนเงิน กู้การซื้อ สลับบัญชี
- [ ] ตัดสินราคาและโควตาจากต้นทุนจริง

## 5. Firebase

- [ ] เครื่องหรือ CI ที่ build เพื่อปล่อยต้องมีไฟล์ตั้งค่าทั้งสอง (ไม่อยู่ใน git — ดู [README](../README.md) หัวข้อ Firebase) ไม่มีไฟล์ build ผ่านแต่ Firebase ไม่ทำงาน
- [ ] เปิด Crashlytics และ Google Analytics ใน console อัปโหลด APNs key และเปิด Push Notifications ของ App ID
- [ ] ปิด Google signals และการแชร์ข้อมูลที่ไม่ใช้ ตั้งระยะเวลาเก็บของ Analytics แล้วใส่ใน [legal/](legal/)
- [ ] build iOS สำหรับสโตร์ด้วย `FIREBASE_ANALYTICS_WITHOUT_ADID=true` เพื่อไม่รวมส่วนรหัสโฆษณา
- [ ] ทดสอบบนเครื่องจริง: เปิด/ปิดสวิตช์ทั้งสาม รับการแจ้งเตือนทดสอบ ทดสอบ crash แล้วเห็นใน console และตรวจว่าไม่มีข้อมูลส่งออกตอนปิดอยู่
- [ ] ตัดสินใจว่าจะส่งการแจ้งเตือนเรื่องอะไร (ตอนนี้ส่งได้จาก console เท่านั้น การส่งรายบุคคลต้องเก็บรหัสใน Supabase และมีฟังก์ชันฝั่ง server) และ Android ยังไม่แสดงข้อความขณะเปิดแอปอยู่

## 6. เอกสารและสโตร์

- [ ] แทนค่าใน [วงเล็บเหลี่ยม] ของไฟล์ใน [legal/](legal/) ให้ผู้รู้กฎหมายตรวจ แล้วเผยแพร่เป็นหน้าเว็บ
- [ ] ใส่ `TERMS_URL` และ `PRIVACY_URL` ใน `app/env.json`
- [ ] ใส่ URL หน้าลบบัญชีใน Play Console (Data safety)
- [ ] ผู้ดูแลมีขั้นตอนรับคำขอลบทางอีเมล: ลบไฟล์ในโฟลเดอร์ `entry-photos/<user id>/` ลบลูกค้าใน RevenueCat แล้วจึงลบผู้ใช้ใน Authentication
- [ ] กรอก App Privacy (App Store) และ Data safety (Play) ตามตารางข้างล่าง

## 7. ทดสอบบนเครื่องจริงที่ยังค้าง

- [ ] อัปโหลดรูปหลังเปลี่ยน policy พื้นที่
- [ ] พื้นที่เต็มแล้วข้อความถูกต้อง
- [ ] ลบรูปจริงหลัง 30 วัน (ย้อนวันลบของรายการทดสอบแล้วเรียก `purge-photos`)
- [ ] ลบบัญชีทดสอบ (ใช้บัญชีแยก) แล้วตรวจว่าข้อมูลและไฟล์หายหมด

## 8. ก่อนปล่อย

- [ ] ตั้ง environment `production` และ secret ตาม [deploy.md](deploy.md) แล้วรันแต่ละ workflow ให้ผ่านอย่างน้อยหนึ่งครั้ง
- [ ] deploy ฟังก์ชันทั้งหมดและ apply migration ให้ครบก่อนออกแอปเวอร์ชันใหม่
- [ ] push branch และ merge เข้า `main`
